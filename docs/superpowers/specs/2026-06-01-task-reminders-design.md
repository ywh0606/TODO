# 任务提醒功能设计

日期：2026-06-01

## 背景

当前 TODO 应用已经支持任务截止日期、优先级、过滤视图、习惯提醒、番茄钟通知和桌面宠物奖励。任务模块目前更偏向“记录事项”，缺少真正提醒用户的能力。用户希望优先提升任务管理实用性，解决“容易忘记做”的痛点。

本设计将任务系统升级为支持具体截止时间、相对提醒和逾期提醒的完整提醒体验版。

## 目标

- 任务可设置截止日期和具体截止时间。
- 任务可设置相对提醒方式：不提醒、到期时、提前 5 分钟、提前 30 分钟、提前 1 小时、提前 1 天。
- 到达提醒时间时弹出系统通知。
- 应用启动或从托盘恢复窗口时，对逾期未完成任务提醒一次。
- 任务列表中清楚展示截止时间、提醒方式和逾期状态。
- 保持第一版范围可控，不引入提醒中心、重复任务或任意自定义提醒日期时间。

## 非目标

本版本不实现：

- 重复任务提醒。
- 任意自定义提醒日期时间。
- 稍后提醒 / 延迟提醒。
- 独立提醒中心页面。
- 多设备同步。
- 后台周期性逾期提醒。

## 用户体验

### 创建任务

任务输入区域支持填写：

- 任务标题。
- 优先级。
- 截止日期。
- 截止时间。
- 提醒方式。

提醒方式以相对选项为主：

- 不提醒。
- 到期时。
- 提前 5 分钟。
- 提前 30 分钟。
- 提前 1 小时。
- 提前 1 天。

如果任务没有设置截止日期或截止时间，则提醒方式选择禁用。只有日期没有时间的任务仍可用于“今天 / 即将到来 / 逾期”判断，但不参与精确到点系统通知。

### 编辑任务

任务项内联编辑继续支持标题、优先级和截止日期，并新增：

- 截止时间。
- 提醒方式。

当用户修改截止日期、截止时间或提醒方式时，系统清空该任务的 `remindedAt`，允许新提醒再次触发。

### 任务列表展示

任务项展示更明确的时间信息，例如：

- `今天 14:30`
- `明天 09:00`
- `6月5日 18:00`
- `已逾期 · 昨天 20:00`

如果设置了提醒，则展示提醒说明，例如：

- `到期时提醒`
- `提前 30 分钟提醒`

逾期未完成任务显示红色“已逾期”状态。已完成任务不显示逾期强调。

### 系统通知

#### 到点提醒

当任务达到计算出的提醒时间时，主进程弹出系统通知。通知内容示例：

- 标题：`任务提醒`
- 内容：`提交日报 · 今天 18:00 截止`

如果到点时任务已完成、已删除、提醒已关闭或截止时间已变更，则不通知。

#### 逾期提醒

应用启动时检查一次逾期未完成任务。从托盘恢复窗口时也检查一次。

如果存在逾期任务，则弹出汇总通知，例如：

- 标题：`你有 3 个逾期任务`
- 内容：`打开清单查看并处理。`

逾期提醒不做后台周期提醒，避免打扰用户。窗口隐藏到托盘后再恢复，可以再次触发一次逾期检查。

## 数据结构

当前任务继续使用 `dueDate` 字段表示截止日期，并新增 `dueTime` 表示具体时间。这样可以兼容历史上只设置日期的任务，也能明确区分“日期任务”和“精确到点提醒任务”。

```js
{
  dueDate: '2026-06-02T00:00:00.000Z',
  dueTime: '14:30',
  reminder: '30m',
  remindedAt: null
}
```

字段含义：

- `dueDate`：截止日期。继续沿用现有字段；历史任务没有具体时间时仍能正常显示和筛选。
- `dueTime`：截止时间，格式为 `'HH:mm'`；为空时表示该任务只有日期，没有精确提醒时间。
- `reminder`：提醒方式。
  - `null`：不提醒。
  - `'at-due-time'`：到期时提醒。
  - `'5m'`：提前 5 分钟。
  - `'30m'`：提前 30 分钟。
  - `'1h'`：提前 1 小时。
  - `'1d'`：提前 1 天。
- `remindedAt`：最近一次到点提醒发送时间，用于避免重复通知。

旧任务没有 `dueTime`、`reminder` 和 `remindedAt` 时保持兼容，不需要强制迁移。

## 提醒时间计算

提醒时间由 `dueDate`、`dueTime` 和 `reminder` 计算。先把 `dueDate` 的年月日与 `dueTime` 的时分组合为任务截止时间，再计算提醒时间：

- `at-due-time`：提醒时间等于任务截止时间。
- `5m`：任务截止时间减去 5 分钟。
- `30m`：任务截止时间减去 30 分钟。
- `1h`：任务截止时间减去 1 小时。
- `1d`：任务截止时间减去 1 天。

如果任务缺少 `dueDate`、缺少 `dueTime`、`reminder` 为 `null`，或计算出的提醒时间已经过去，则不调度到点提醒。创建或编辑任务时不立即弹出已经错过的到点提醒；该任务后续只通过逾期提醒覆盖，避免用户编辑旧任务时被系统通知打扰。

## 架构设计

### Renderer 层

`TaskInput.vue` 负责创建任务时采集截止日期、截止时间和提醒方式。

`TaskItem.vue` 负责展示和内联编辑截止时间、提醒方式、逾期状态。

`FilterBar.vue` 暂不新增筛选项，继续保留“全部 / 今天 / 即将到来 / 已完成”，但筛选逻辑需要兼容带时间的 `dueDate` 和 `dueTime`。

`taskStore.js` 负责：

- 创建任务时写入 `dueDate`、`dueTime`、`reminder`、`remindedAt`。
- 更新任务时允许修改 `dueDate`、`dueTime`、`reminder`、`remindedAt`。
- 当 `dueDate`、`dueTime` 或 `reminder` 变化时清空 `remindedAt`。
- 保存任务后通过现有 `saveTasks()` 触发主进程持久化。

### Main 层

新增 `electron/taskReminders.js` 作为纯逻辑模块，包含：

- 提醒时间计算。
- 判断任务是否可调度。
- 判断任务是否逾期。
- 格式化通知内容。

`electron/main.js` 负责：

- 应用启动后读取 `tasks.json` 并调度任务提醒。
- 每次 `save-tasks` 后重新调度任务提醒。
- 对每个未完成、已设置提醒、有截止日期和截止时间且未提醒过的任务创建 `setTimeout`。
- 到点后重新读取任务，确认任务仍有效，再弹出系统通知。
- 通知成功后写入 `remindedAt` 并保存任务。
- 应用启动和窗口显示时检查逾期未完成任务。

主进程是提醒调度的权威来源，渲染进程只负责编辑任务和显示状态。

### 逾期提醒去重

主进程维护运行期状态：

```js
let overdueReminderShownForWindowSession = false
```

规则：

- 应用启动或窗口显示时检查逾期任务。
- 如果本次窗口显示周期已提醒过，则不重复提醒。
- 窗口隐藏到托盘后重置该状态。
- 若没有逾期任务，不弹通知。

## 错误处理

- 保存失败：沿用现有 `saveTasks()` 的 try/catch，记录错误，第一版不新增 toast。
- 通知不可用：主进程使用 `Notification.isSupported()` 检查，不支持时跳过通知并记录日志。
- 无效提醒组合：没有 `dueDate`、没有 `dueTime`、非法 `reminder` 或已完成任务均不调度到点提醒。
- 旧数据兼容：旧任务缺少新字段时不报错，创建和编辑后再写入新字段。

## 验收标准

- 用户可以创建带截止日期、截止时间和相对提醒方式的任务。
- 到提醒时间后，未完成任务会弹出系统通知。
- 已完成任务不会弹出到点提醒。
- 启动应用或从托盘恢复窗口时，逾期未完成任务会汇总提醒一次。
- 任务列表能显示截止时间、提醒方式和逾期状态。
- 旧任务数据仍能正常加载。
- `npm test` 通过。
